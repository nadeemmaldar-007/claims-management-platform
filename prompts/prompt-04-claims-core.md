- **Assign** (`POST /claims/{n}/assign`, MANAGER, body `officerUserId`): the target must be an active OFFICER of the claim's market, else 422 (use `BusinessRuleException` with a clear message that names `officerUserId`). From SUBMITTED it behaves like a pick-up for that officer (status UNDER_REVIEW, ASSIGNED entry, `ClaimAssigned` event). From UNDER_REVIEW, PENDING_INFORMATION or ESCALATED it is a reassignment: status unchanged, timeline REASSIGNED (INTERNAL, naming old and new officer), no event. Other statuses: 409.
- **Assessments** (`POST` and `GET /claims/{n}/assessments`, OFFICER, MANAGER): only in UNDER_REVIEW or ESCALATED; the caller must be the assigned officer or a manager (an officer who is not the assigned officer gets `ForbiddenException`, 403); the system computes `deductible_applied` and `recommended_payout` with `AssessmentCalculator` from the claim's snapshots; request `assessedLossAmount` (> 0, valid scale), `coverageConfirmed`, `recommendation` (APPROVE, REJECT, ESCALATE), `notes` (max 2000); timeline ASSESSMENT_RECORDED (INTERNAL); 201 with a `Location` header; the list is newest first; claimants never reach these endpoints (403).
- **Information requests** (`POST` and `GET /claims/{n}/information-requests`, `POST .../{requestId}/respond`, `POST .../{requestId}/cancel`): creating needs UNDER_REVIEW and the assigned officer or a manager; `question` 10 to 1000 characters, `dueInDays` 1 to 30 (default `app.sla.information-request-default-days`); creates an OPEN request with `due_at`, moves the claim to PENDING_INFORMATION, timeline INFORMATION_REQUESTED, event `InformationRequested`. Respond: CLAIMANT of that claim only, request must be OPEN (else 409 `INFORMATION_REQUEST_NOT_OPEN`), `responseText` 10 to 2000 characters; marks RESPONDED; if no OPEN request is left, the claim returns to UNDER_REVIEW; timeline INFORMATION_PROVIDED; event `InformationProvided`. ## 11. KNOWN PITFALLS FOR THIS PROMPT

1. **Optimistic lock errors surface at commit** unless you `saveAndFlush` inside the service method; for pick-up catch `ObjectOptimisticLockingFailureException` right there and translate it.
2. `@Version` fields are managed by Hibernate: never set them in code; use the wrapper type `Long`.
3. `ClaimNumberGenerator` must run in the same transaction as the claim insert (`MANDATORY`); the pessimistic lock is released at commit, so keep that transaction short and generate the number after all validation.
4. Compare `BigDecimal` with `compareTo`; never `equals` (2.0 differs from 2.00). Normalise the scale with `MoneyRules` before storing.
5. Never return entities from controllers; map inside the transaction (`open-in-view=false`). Avoid N+1 queries with `@EntityGraph` on the specification query.
6. Static path `/claims/queue` versus `/claims/{claimNumber}`: Spring prefers the literal; keep the test.
7. Out-of-scope means **404**, in-scope but not allowed means 403, wrong state means 409, rule violation means 422, bad input means 400. Do not mix them up.
8. Assessment notes and recommendations are internal: not in the claimant's detail, not in PUBLIC timeline messages, not in logs.
9. Incident date rule is "not later than tomorrow in UTC" (documented amendment); the five-year limit uses the injected `Clock`.
10. `Specification` filters must not use optional-null JPQL; build predicates only for the filters that are present. `submittedTo` is inclusive: compare with the start of the next day (exclusive).
11. Jackson serialises `BigDecimal` as a number: do not format amounts as strings. Instants are ISO-8601 strings.
12. The H2 pessimistic lock and the concurrency tests need real separate transactions: use `TransactionTemplate` or separate MockMvc calls from several threads, never a single test-level transaction.
13. Tests share one database: unique incident dates per test and unique user ids; never assert global counts, only counts for your own claim numbers.
14. Every Maven command needs `JAVA_HOME` = JDK 21. Do not use `curl` (PowerShell alias); the smoke script exists for that.
